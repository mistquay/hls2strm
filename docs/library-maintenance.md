# 媒体库维护使用说明

入口：侧栏「媒体库维护」，或输出库的「库维护（NFO、空间与清理）」。影片列表选择影片后点「维护与清理」，详情页也有「维护」入口。

## 首次使用

1. 更新后重启后端并使用本次前端构建。已有数据库从 v26 升到 v27；升级前自动备份到数据库旁的 `<数据库名>.pre-v27-<时间戳>.bak`。新数据库不额外备份空库。
2. 选择要维护的输出库，点「扫描磁盘与 NFO」。不选库表示全部配置库。
3. 扫描完成后刷新结果，检查根目录健康、NFO 关联及解析状态；首次建议先核对少量已知影片。
4. 在「本地资料与筛选」或「筛选清理」中组合类型、标签、演员、发行日期/年份、厂牌、时长、目录大小等条件。
5. 选择当前页、跨页选择，或选择全部筛选结果。全选后可取消某些行；改变筛选会清空选择。
6. 选择清理动作，生成预览。检查命中资料、库范围及每组的完整文件清单，再确认执行。

本服务不调用 MDCNG 重新刮削，也不更改它的配置。需要在 MDCNG 重新补刮时，由用户单独处理。

## NFO 资料

支持标准 `<movie>` NFO：标题、番号型 uniqueid/num、premiered/releasedate、year、genre、tag、actor/name、studio、director、set、runtime、plot 等。runtime 按分钟转换为秒。

优先选与 STRM 同名的 NFO，再尝试 `movie.nfo`，最后接受唯一 NFO。多个无法唯一选择的文件、番号/明确版本不一致、发行日期相互矛盾都会标记冲突。

- 本地资料独立保存，不覆盖源站字段，也不因读取 NFO 而重新归库、搬运文件。
- 类型和标签分别保存；本地演员姓名不冒充站点演员 ID。
- 只有年份的资料只能用于年份条件，不伪造成完整日期。
- 默认按可信 NFO 字段筛选。可明确选择“NFO 优先，源站补缺”；预览保留所使用的字段来源。
- 日期/类型未知默认不满足对应条件；“不包含某类型”也不会把未知类型自动纳入。可以明确勾选包含未知，但冲突和损坏资料仍需处理。
- NFO 后来损坏或丢失时，保留最后成功资料作为历史快照；默认不把过期快照当作当前删除依据。
- 已经在首次扫描前连同 NFO 删除的影片，不能凭空恢复 NFO 信息，只能利用已有影片记录核对缺失。
- 解析拒绝 DTD、外部实体、超过 2 MiB 或层级过深的 XML，不访问 NFO 中的链接。支持 XML 编码声明/BOM。

NFO 和 STRM 的快照包含内容摘要，预览执行前检查内容变化。图片使用文件身份、大小和时间等指纹核对，不为统计而整库读取图片内容。

未纳管但有有效 NFO 的目录可点「关联影片」，选择番号一致的已知影片并确认。此操作只建立维护关联，不改写 STRM URL。共享目录、未知文件、链接或实体视频会阻止不明确的整片清理。

## 清理动作

| 动作 | 用途与边界 |
|---|---|
| 只清理资源文件 | 可选额外剧照、海报、主背景图、缩略图、NFO、预告片、字幕；默认只选额外剧照 |
| 删除影片副本 | 当前库范围会包括该影片在同库的收件和整理副本；全局范围展开到所有已配置库 |
| 磁盘已删，同步记录 | 复核确实缺失后移除失效输出关联，不再次删除文件 |

额外剧照按自然文件名排序保留前 N 张，例如 fanart2 在 fanart10 前面。N=0 表示删除该目录内所有匹配额外图片。只处理固定预览清单，不执行过程中扩大目录范围；空目录可能保留。

删除影片默认禁止返回所选范围：

- 当前库：其他库仍可收录同一影片。
- 全局：所有站点的新旧来源、订阅、补源、规则归库、核对补回、手动加入和重写都不能重新输出该版本。
- 普通版和 `-U` 版独立；同片整理迁移排除记录，不因换了数据库 ID 而解除。
- 保留影片身份、来源和排除记录，防止下次抓取被当作新片。原有“删除源”仍是来源级操作，与停止收录分开。
- 取消“完成后停止收录”表示允许以后补回，预览会明确说明。

只清资源不会移除影片。自管库会记住主动清理的资源类型，避免刷新/核对立即重建 NFO、海报等；可在「记录与恢复」中解除资源禁补记录。MDCNG 自己的重刮不受本服务控制。

## 手动从磁盘删片

在「磁盘差异」中，每库可选择：

- **按现有设置补回**：兼容原来的全局 external_restore 设置和核对规则。
- **缺失先等待确认**：先建立成功扫描基线再启用；抓取和核对遇到已输出文件缺失时不会直接补回，等待人工核对。

改名、移动会按 STRM 内容找回；尚未写出的待归库记录不算磁盘删除。只删图片或 NFO 不会被判断为整片删除。

根目录离线、权限错误、扫描中断不会产生可信的缺失退库结论。整库清空需要单独勾选确认，并且必须有历史成功基线和相同的根目录身份；没有这些证据时只报告，不批量退库。

## 回收、永久删除与恢复

整片清理默认回收；额外图片默认永久删除以释放空间，最终确认页明确显示。选择回收时可设置本批保留天数，0 天表示永久删除。

回收位置为每个原根目录下 `.hls2strm-trash/maintenance/<执行任务ID>/`，保留原相对路径。回收文件按已确认期限，由现有「回收区清理」定时任务处理；停用该定时任务会延后过期清理。

保留期从本轮执行收尾开始计算，不会把排队或暂停时间算进保留期。失败或未完成组的回收文件受到保护；明确放弃未完成项后才按新期限处理已回收文件。

**同盘回收不会立刻释放磁盘空间。** 页面区分回收的逻辑大小、永久删除的逻辑大小、回收区占用以及操作前后的可用空间观测。硬链接、稀疏文件、快照、其他并发写盘都会影响实际可用空间，不能把观测差值全算成本任务释放量。

恢复流程：记录与恢复 → 对清理任务点「预览恢复」→ 核对冲突 → 确认恢复。原路径已有文件时保留两侧，整组跳过，不覆盖。恢复完成后恢复原库关联，只解除本次清理产生的排除/资源禁补，不清除其他独立记录。

永久删除或回收已经过期的文件不能恢复；解除排除只允许以后重新收录，不会自动恢复原刮削文件。

## 任务、失败与安全边界

- 支持在任务中暂停、恢复、取消。取消只停止后续项，不撤销已经处理的文件。
- 单组变化或失败会记录原因，继续其他已确认组；完整清单可分页查看。
- 失败后可重试未完成项；也可在任务停止后明确放弃未完成项，已动过的文件不会自动回滚。必要禁收保护按实际结果保留。
- 文件操作前保存意图。进程在文件移动之后、数据库记账之前中断，可以核对回收目标后继续，不重复移动或覆盖。
- 清理执行与应用内文件变更按组互斥。外部 MDCNG 不受这个锁控制，执行时应暂停对应目录的外部刮削写入。
- 活跃恢复任务保护对应回收文件不被自动过期清理。
- 有未完成文件、可恢复文件或排除规则引用时，不能直接删除其任务凭据。
- 完整扫描分代发布，旧快照在新扫描失败时保留；过期资产索引定期在扫描收尾时清除，固定预览自带证据不依赖旧索引行。
