# 番号别名归并、重复 STRM 清理与版本起播备用

状态：开发方案，尚未实施，2026-10-13。
本稿整合了 `work-identity-and-version-fallback-plan.md`（下称“旧稿”），两者冲突时以本稿为准。

## 结论

| 问题 | 做法 |
| --- | --- |
| `259LUXU-1850-U` 和 `LUXU-1850-U` 被当成两部 | 匹配键 v2 认出数字厂牌前缀和无码厂牌的各种写法。同键同版本的新源自动归到一部 |
| 已经写出的重复 strm（可能已被 MDCNG 整理、被 Emby 收录） | 新增维护操作「同片整理」，先预览再确认。每组留一部，其余并入：并入者的文件走现有“移出库”流程清掉，刮削目录进回收区。旧 slug 继续能播 |
| 普通版与 -U 版 | 仍是两部作品，各自有元数据、归库、strm 和多画质文件，不合并 |
| 互为起播备用 | 新增设置「版本起播备用」，默认关闭。开启后，本版已知的源都起播失败，才改用另一版本的已知源 |

截图里的三条最终变成两条：`LUXU-1850`（普通版）和 `LUXU-1850-U`（-U 版，吸收 `259LUXU-1850-U` 的源）。

与旧稿的取舍：

- **采纳旧稿的部分：**
  - 普通版和 -U 版各自独立，`@` 只表示画质。
  - 备用默认关闭，只在本版起播失败后才用。
  - 不跨版本改画质清单，不动 Emby 和刮削器的数据库。
  - 锁定的源、字幕不回退、只要直连这三个限制都不能被绕过。
  - 直链 strm 没有备用能力。
- **和旧稿不同的部分：**
  - 旧稿默认把重复文件物理保留，本稿默认清理。用户明确要清理，而且 MDCNG 重刮不花成本。不想清理的组可以在预览里跳过。
  - 旧稿的单影片备用开关、三态版本（普通/-U/未知）、人工别名决定表、历史输出表都不做。现有的按内容找文件，加上 slug 别名表，已经够用。
  - 数字前缀：旧稿只认白名单。本稿用“3 位数字 + 字母厂牌”的通用规则，另有代码内的例外表，再用预览里的冲突校验兜底。

## 二、兼容边界（不能破坏的现有行为）

1. **作品身份不变。** 仍是 `(code_key, uncensored)`，只换 `code_key` 的算法。slug、显示番号、strm 路径都不因新规则改变。
2. **多画质版本不变。** 包括 `libraries.versions`（emby/suffix）、`version_labels`、`own_versions`（按 `/play/{slug}@档位` 认归属），以及外部整理库“收件目录里不写、整理后在主文件旁补”的时机。版本档位只来自本作品自己的源。备用开关不增删任何版本文件。
3. **`@` 只表示画质。** `/play/{slug}@720p.m3u8` 借用另一版本时，`want` 原样往下传。
4. **字幕仍是源的属性。** `_attach_found` 里中字变体的处理不变。
5. **五库互斥和归并不变。** 合并只改 outputs 归属，后续交给现有的 `settle`、`apply_rules`，不直接去写别的库的文件。
6. **文件操作只走现有函数。** 删除用 `_remove_files`（删 strm 和多画质附件，整理目录里独占的影片目录进回收区），写入用 `_output_one` / `_output_all`。不另写删文件的逻辑。
7. **删掉的源不复活。** 用户删掉的源（status=removed）合并后仍是 removed。
8. **直链 strm 不受影响。** `play_mode=direct` 写出的 strm 里是 CDN 直链，不经过本服务，备用不生效。设置页要注明。
9. **批量文件变更走现有框架。** 用 `Operations` 的预览、确认、指纹校验，执行时持有 `file_changes.exclusive()`，中断后可以续做。

## 四、P1：匹配键 v2、入库与查找

### 4.1 `code_key(code, maker="")`

按顺序匹配，命中一条就返回：

1. 用 NFKC 规整（全角转半角）、去首尾空白、转大写。空串返回空串。
2. **FC2：** 规则不变，输出 `FC2PPV-{编号}`。
3. **无码厂牌（`STUDIOS` 表）：** 匹配 `^(别名)[\s_-]*(\d{6})[\s_-]+(\d{2,3})$`，输出 `{规范名}-{日期}{分隔符}{序号}`。日期和序号原样保留，不去前导零；分隔符用该厂牌自己的约定。

   | 规范名 | 别名 | 分隔符 | 例 |
   | --- | --- | --- | --- |
   | CARIB | CARIB、CARIBBEANCOM | `-` | `CARIB-100826-001` |
   | CARIBPR | CARIBPR、CARIBBEANCOMPR | `_` | `CARIBPR-100826_001` |
   | 1PON | 1PON、1PONDO、PONDO | `_` | `1PON-100826_001` |
   | 10MU | 10MU、10MUSUME、MUSUME | `_` | `10MU-100226_01` |
   | PACO | PACO、PACOPACOMAMA | `_` | `PACO-100826_001` |

   `PONDO`、`MUSUME` 是 MissAV 的写法（见 `tests/test_missav.py`）。表可以扩展，加厂牌只加表项。
4. **HEYZO：** 匹配 `^HEYZO[\s_-]*(?:HD[\s_-]*)?(\d{3,4})$`，输出 `HEYZO-{编号转整数}`。
5. **东京热：** 匹配 `^(?:TOKYO[\s_-]*HOT[\s_-]*)?([NK])[\s_-]?(\d{4})$`，输出 `TOKYOHOT-{N 或 K}{4 位编号}`。
6. **不含字母的日期型：**
   - `\d{6}[\s-]\d{3}` 输出 `CARIB-…`（沿用现有“横线就是 Caribbeancom”的约定）。
   - `\d{6}_\d{2}` 输出 `10MU-…`（两位序号只有 10musume 用）。
   - `\d{6}_\d{3}`：`maker` 能在 `MAKER_STUDIOS` 里匹配到就补上厂牌，例如一本道/1pondo 对应 1PON，カリビアンコムプレミアム/caribbeancompr 对应 CARIBPR，パコパコママ/pacopacomama 对应 PACO（不分大小写，子串匹配）。匹配不到就保持裸键 `100826_001`，和现在一样，不跨厂牌猜。
   - 其他不含字母的：沿用现有逻辑。
7. **数字厂牌前缀：** 第一段形如 `\d{3}[A-Z]{2,}`、且不在 `KEEP_PREFIX`（代码常量，初始为空）里时，去掉这 3 位数字。例：`259LUXU-1850` 变成 `LUXU-1850`，`300MIUM-001` 变成 `MIUM-1`。1–2 位或 4 位数字开头的不动，如 `3DSVR`、`1000GIRI`。
8. **其余：** 沿用现有逻辑（字母前缀 + 编号去前导零 + 后续分段原样保留）。

另外提供：

- `is_native(key)`：键以 `STUDIOS` 的规范名、`HEYZO-`、`TOKYOHOT-` 开头，或不含字母时，返回 True。
- `edition(code, uncensored, maker="") -> bool`：返回 `uncensored and not is_native(code_key(code, maker))`。

必须通过的例子（同一行的写法要得到同一个键）：

| 写法 | 键 |
| --- | --- |
| `259LUXU-1850`、`LUXU-1850`、`luxu1850` | `LUXU-1850` |
| `300MIUM-001`、`MIUM-1` | `MIUM-1`（改旧断言） |
| `T28-001` | `T28-1` |
| `KIRA-020-2` | `KIRA-20-2` |
| `3DSVR-0123` | `3DSVR-123` |
| `SSIS-001`、`ssis00001`；FC2 各写法 | 和现在一样 |
| `PONDO-100826_001`、`1pon-100826_001`、`1pondo_100826_001` | `1PON-100826_001` |
| `1pondo-010120_001` | `1PON-010120_001` |
| `carib-100826-001`、`caribbeancom 100826-001`、`100826-001`、`100826 001` | `CARIB-100826-001`（改旧断言） |
| `MUSUME-100226_01`、`10mu-100226_01`、`100226_01` | `10MU-100226_01` |
| `100826_001`（maker 为空） | `100826_001` |
| `100826_001`（maker 为一本道） | `1PON-100826_001` |
| `heyzo_hd_1234`、`HEYZO-1234` | `HEYZO-1234` |
| `tokyo-hot-n1234`、`n1234` | `TOKYOHOT-N1234` |

另外，`caribpr-100826_001` 和 `1pon-100826_001` 必须得到不同的键。

### 4.2 原生无码不分版本

凡是用 `uncensored` 判断是否同片、拼 slug、核对查找结果的地方，都改为先经过 `edition()`：

- `db._attach`（找作品和新建作品）
- `engine._slug_for`
- `sites.find_by_code`（核对时两边都要规整）
- `play._discover_for`、`engine._lookup` 传进去的版本

这样原生番号就不会产生 `-u` 的作品。存量里原生番号却标了 `uncensored=1` 的影片，迁移时不改（改了会影响规则库归属），交给 P2 处理（见 5.1）。

### 4.3 SupJav

- `parse_title` 处理日期型番号时，不再把 `_` 换成 `-`。
- 标题里日期前如果有厂牌词（1pondo、carib、caribbeancompr、10musume、paco 等），连同厂牌一起作为番号，再交给 `code_key` 规整。
- 补测试，构造标题即可。

### 4.4 查找时试多种写法

- **`codes.spellings(code, prefixes) -> list[str]`**，生成候选写法，去重保序：
  1. 作品番号原样。
  2. 去掉或补上 3 位数字前缀的写法。补前缀用 `prefixes`（厂牌 → 3 位数字），从 `videos.code` 学：`SELECT DISTINCT code FROM videos WHERE code GLOB '[0-9][0-9][0-9][A-Z]*'`，每个厂牌取出现最多的前缀。启动时算一次，入库遇到新的带前缀番号时增量更新。
  3. 无码厂牌的长短名写法，如 `1PON`、`1PONDO`、裸日期。
- **`Site.key_candidates(code, subtitle, uncensored, spellings)`**：默认对每个写法调用 `key_for` 再去重。站点有自己的厂牌写法时覆盖，例如 MissAV 的 `pondo-`、`musume-` 和裸日期。
- **`find_by_code`：**
  - 拼地址类站点：按候选依次抓详情核对，命中即停，最多试 3 个。每试一次就是一次站点请求，过 CF 的站代价高。
  - 搜索类站点（`lookup_verified`）：用不带数字前缀的写法搜一次。
  - 核对一律比较 v2 键和经过 `edition()` 规整后的版本。
- 现场找源（`play._discover_for`）和补源共用 `find_by_code`，自动得到同样的改进。

### 4.5 迁移（只改库：不动文件，不合并作品）

- 用 v2 算法（带上 `maker`）重算所有影片的 `code_key`。
- 键变了的影片，删掉它们在 `source_checks` 里 `found=0` 的记录。以前可能是写法不对才没找到，之后补源会重查。
- 迁移后出现“同键同版本有多部影片”是预期的，等 P2 整理。在此之前，`_attach` 按现有的 `ORDER BY status='active' DESC, id` 把新源挂到其中一部，不报错。
- `_update_work` 重算键时带上 `maker`。这样详情补全后，键可能从裸日期变成带厂牌的，从而和别的影片撞键。热路径里不做合并，留给 P2 预览。
- 按番号排序用的是 `code_key`，排序会随之变化（LUXU 排到 L 下面），可以接受。
- 每个阶段需要的表结构各加一个迁移（v22、v23 …），沿用现有 `MIGRATIONS` 的写法。

## 五、P2：同片整理（合并同版重复，清理文件）

### 5.1 分组和保留项

- **组：** `code_key` 非空、`(code_key, edition(...))` 相同的影片有 2 部及以上。
- **版本标记更正：** 单独存在、原生番号却标了 `uncensored=1` 的影片，也列出来，单独算一类。
- **选保留项：** 每组留一部，其余并入。按以下顺序比较：
  1. 状态是 active。
  2. 有输出在外部整理目录里，也就是 MDCNG 已整理、Emby 能看到的那份。按内容索引 `strm.index` 判断。
  3. 播放记录次数（`play_history`）。
  4. 已写出文件的输出数。
  5. id 小。
- 预览里可以手动指定某组的保留项，或跳过某组。改动通过请求参数传入，重新计算预览。

### 5.2 冲突校验（防误合）

两部都有详情时，下面任一情况就标为“疑似不同片”，默认不执行，用户在预览里勾选了才执行：

- 发行日期不同。
- 时长都已知，且相差超过 max(120 秒, 10%)。

### 5.3 预览

用 `Operations` 现有的预览和确认，新加一个 kind（如 `dedupe`），`operation_items` 里每组一行。展示内容：

- **计数：** 组数、并入影片数、要删的 strm 数（含多画质附件）、要移进回收区的整理目录数、找不到文件的输出数、预计换库的组数、疑似冲突组数、版本标记更正数。
- **每组：**
  - 保留项和并入项各自的 slug、标题、状态、所在库、strm 路径（标出哪些在整理目录里）、源站点、播放次数。
  - 合并后的预计归属：按排除库关系在本地推算，会换库的标出来。
- **列表：** 冲突组和会换库的组全部列出；其余组列样例，可以翻页。

### 5.4 执行（每组按顺序做，可重入）

在 `file_changes.exclusive()` 里逐组处理：

1. **校验。** 组内影片、键、版本、各输出路径要和预览一致，不一致就对这一组抛 ScopeChanged，已完成的组保留。
2. **先清文件，再改库。** 顺序不能反：并入者的 slug 还没变成别名时，按内容索引找到的只会是它自己的文件。
   - 对并入者的每个输出调用现有的 `_remove_files(lib, 并入者 id, 并入者 slug, strm_path)`，然后删掉这条输出记录。
   - 记下它原来在哪些库、via 是什么。
3. **在一个事务里改库：**
   - `sources`（连带 `source_lines`）改挂到保留者，状态原样，removed 的不复活。
   - 合并 `source_checks`：found 取较大值，checked_at 取较新的。
   - 并入者在、保留者不在的库：给保留者加一条输出，`strm_path` 为空，via 沿用并入者的。
   - `play_history`、`crawl_items` 的 video_id 改成保留者，slug 文本不改。
   - 删掉并入者的 `archives` 记录和 `removed_from`。归档目录里的文件原样保留，日志里列出路径。
   - 保留者为空的元数据字段用并入者的补上，已有的值不覆盖。
   - 写 `video_aliases`：并入者 slug 指向保留者；原来指向并入者的别名也改为指向保留者。
   - 删除并入者的 `videos` 行。
   - 版本标记更正：`uncensored` 改为 0。
4. **重写保留者的输出：**
   - 调用 `_output_all`。多画质档位可能因为多了源而增加，按现有机制在主文件旁补。
   - 新加的输出调用 `_output_one`。有排除库的库按现有规则等归并后再写。
   - 调用 `apply_rules`，置 `_settle_wanted`。
5. 记下游标，处理下一组。

### 5.5 旧 slug 兼容（`video_aliases`）

表结构：`video_aliases(slug TEXT PRIMARY KEY, video_id INTEGER NOT NULL, created_at INTEGER NOT NULL, job_id INTEGER)`，另建 `video_id` 索引。

- **`db.get_video(slug)`：** 查不到时再查别名。这样 `/play/{旧slug}.m3u8`、`/play/{旧slug}@720p.m3u8`（保留 want）、`/api/resolve/play/...` 和网页链接都会落到保留者上。别名查完之前不触发 `discover`。
- **`db.video_keys()`：** 把别名也带上（旧 slug 对应保留者 id），这样残留的旧文件能被内容索引认到保留者名下。
- **`find_by_video`：** 同一部影片找到多个文件时，URL 里是现行 slug 的排在前面，`locate` 和 `pick` 就不会把旧文件选成主文件。
- 别名不参与 `_attach` 的匹配，匹配仍只靠 `code_key`。

### 5.6 已整理、已入 Emby 的文件会怎样

| 并入者的文件在哪 | 怎么处理 | Emby 那边 |
| --- | --- | --- |
| 收件目录（MDCNG 没整理或拒刮了） | 删掉 strm 和多画质附件 | 本来就看不到 |
| 整理目录，独占一个影片目录 | 删掉 strm 和附件，整个目录（nfo、图片、花絮）移进 `<整理目录>/.hls2strm-trash/<日期>/`。放满 `trash_days` 天后自动删除，设为 0 则直接删 | 下次扫库或实时监控后，这个条目消失；保留者的条目不动 |
| 整理目录，和别的片共用目录 | 只删 strm 和附件。nfo、图片留着，在结果里列出，不按文件名猜着删 | 同上 |
| 找不到（例如在 MDCNG 的刮削失败目录，不在本服务认得的根目录下） | 不动，在结果里列出。旧 slug 有别名，仍能播 | — |
| 自管库（没设外部整理目录） | 走现有 `writer.remove`：strm、nfo、封面、附件一起删 | — |

补充说明：

- 保留者的 strm 内容不变（slug 没变），MDCNG 不会重刮它，它的 Emby 条目和观看记录都在。
- 被删掉的那个 Emby 条目，观看记录会丢。在意的话，在预览里把保留项换成看过的那部。
- 不修改 Emby 和 MDCNG 的数据库或配置。
- 执行期间不用停 MDCNG：这一步只删文件。需要换库的组除外，它们会按正常新片流程往新库写入。

### 5.7 入口

在影片库页（或现有的维护入口）加「同片整理」，展示复用 `operation-preview` 组件，交互参照站点清退。整理可以随时重跑：详情补全后才撞键的那些影片，下次预览会出现。

### 5.8 P2 测试

- **清理与保留：** 两部重复的 -U 版，保留在整理目录里的那部。并入者的文件按位置处理：
  - 在整理目录独占一个目录：进回收区。
  - 在收件目录：直接删。
  - 和别的片共用目录：只删 strm。
- **多画质附件：**
  - 并入者的附件要一起删。
  - 保留者因为多了源而多出档位时，在它的主文件旁补上。
  - 附件按 slug 认归属，不能串到别的片。
- **旧链接：**
  - 旧 slug 和 `旧slug@720p` 都能播，画质保留。
  - 网页和 API 查旧 slug 得到的是保留者。
- **数据迁移：** removed 的源不复活，`source_checks` 合并，`play_history` 改挂到保留者。
- **换库：** 并入者在优先级更高的库时，保留者经归并进入该库，并移出低优先级的库。
- **预览选项：**
  - 冲突组默认不执行。
  - 可以手动指定保留项。
  - 可以跳过某组。
- **中断与变动：**
  - 中途中断后重跑：已完成的组跳过，没完成的组从头做（先清文件再改库，所以可以重入）。
  - 预览后文件被外部工具挪了位置：按内容重新找到。
  - 关键条件变了：该组报 ScopeChanged。

## 六、P3：版本起播备用（可配置）

### 6.1 设置

- 新增设置 `edition_fallback: Literal["off", "both", "normal_uses_u", "u_uses_normal"] = "off"`。
- 放在设置页「选源偏好」组，标签为“版本起播备用”。四个选项依次是：关闭 / 普通版和 -U 版互为备用 / 只让普通版用 -U 版备用 / 只让 -U 版用普通版备用。
- 说明文字写清楚两点：
  - 直链模式写出的 strm 不经过本服务，这个设置对它不生效。
  - 借用时播的是另一版本的内容：-U 版借普通版会是有码的，两版时间轴也可能不同。

### 6.2 兄弟版本

`code_key` 相同（非空）、版本相反、status 为 active 的影片。可能不止一部，P2 整理前的同版重复也算在内。

### 6.3 选源顺序（改 `Resolver._resolve`）

1. **先试本版的源：** 现有的 `rank` 排序后依次尝试，不变。
2. **再试兄弟版本的已知源：** 条件是设置允许这个方向，且没有指定 `site`（网页手动选源时指定了就不借）。
   - 用同一个 `rank` 排序，参数相同：want、direct_only、remote、冷却、连通性。
   - 排在本版源之后，作为同一轮候选继续尝试。
   - `excluded`（客户端已经试过的、预检失败的）照样生效。
3. **都失败：** 沿用现有的现场找源。只按本版番号找，触发条件也不变（没有被排除的候选时才找）。兄弟版本不做现场找源。
4. **字幕不回退时：** 兄弟版本的源只保留和本版选中的字幕档相同的。本版一个可用的源都没有时，用兄弟版本自己最好的那档。
5. 对兄弟版本的源调用 `_ensure` 时，传兄弟影片本身，`_need` 和刷新详情都用它自己的数据。

`PlaybackSelection.choose` 里“预检失败、排除、再 resolve”的循环不用改：候选键是源 id 加线路 id，跨影片不会冲突。

### 6.4 记录与展示

- **`Resolved`：** 加字段 `requested: dict | None`，借用时填被请求的影片。
- **日志：** 写“播放 X：本版的源都不可用，改用 -U 版 Y 的源 …”。trace 里也写一行，网页试播的诊断能看到。
- **指标：** 加 `play_edition_fallback`。
- **播放记录：**
  - `slug`、`video_id` 记被请求的影片。
  - 新增列 `served_video_id`，记实际提供源的影片。
  - 播放记录页显示“版本备用：Y”。
- **网页播放器：** 播放准备结果（`prepare=1` / `playback_source`）带上实际影片的 slug 和是否借用，播放器显示“版本备用”。
- **影片详情：** 详情接口和 `/api/videos/{slug}` 带上兄弟版本列表（slug、普通/-U、状态），详情页显示“其他版本”链接。
- **不改的东西：**
  - 源的归属不变。
  - 源状态和失败计数各记各的：兄弟版本的源失败照常记在它自己身上。
  - NFO、归库、多画质文件不变。
  - 中转会话固定在起播时的源和线路，播放过程中不会再跨版本切换。

### 6.5 P3 测试

- 设为 off：本版的源全失败时报错，不碰兄弟版本的源。
- 设为 both：
  - 本版的源全失败：改用兄弟版本的源。
  - 本版有源成功：不用兄弟版本的源。
  - 本版的源预检失败：转去用兄弟版本的源。
- 单向的两个选项只在允许的方向上生效。
- 请求 `@720p` 时借用兄弟版本，仍按 720 选档。
- 下面几种情况不能绕过：
  - 指定了 src 时不借用。
  - 字幕不回退的限制仍然有效。
  - direct_only 仍然有效。
- 播放记录写入了 `served_video_id`；网页 prepare 的返回带有备用信息。

## 七、不做的事

- 把普通版和 -U 版合成一部，或者一部作品写出多个主 strm。
- 单影片级的备用开关、三态版本（普通/-U/未知）、人工别名决定表。
- 补源时把搜到的另一版本挂到兄弟影片上，或自动新建兄弟影片。
- 把 NFO、图片迁移到别的库，或修改 Emby、MDCNG 的数据库。
- 播放过程中跨版本换源，或对齐跨版本的续播进度。
- 自动把直链 strm 改写成本服务的地址。

## 八、实施顺序

1. **P0：** 只读审计。
2. **P1：** 匹配键 v2、入库与查找。
3. **P2：** 同片整理。
4. **P3：** 版本起播备用。

每个阶段单独提交，全量测试通过后再进下一阶段。

- P1 上线后立刻不再产生新的重复。
- P2 等 P0 审计结果确认没问题后再执行。
- P3 默认关闭，什么时候上都可以。
