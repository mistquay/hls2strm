# 播放记录

侧栏新增“播放记录”。可以按原样中转 / 302 直连、实际站点、影片番号或标题、交付状态和日期筛选，记录按时间倒序，每页 50 条。点击影片进入影片库对应搜索。筛选保存在页面 URL，刷新后保留。

记录保存当时的影片、站点、源和线路快照，之后源下架、站点停用或影片元数据更新，不会把旧记录显示成另一部影片或另一个站点。

## 记录口径

| 入口 | 记录内容 |
|---|---|
| `GET /play/{name}` | 实际选择的源，以及此次返回的是 302 还是原样中转 |
| `GET /media/{source_id}?s=...` | 当前固定会话实际交付的影片、站点和线路；重复 Range / 清单请求合并到同一条记录 |
| `GET /api/resolve/{name}` | 网关拿到的直连或中转地址，先显示“地址已返回”；后续中转经过本服务后更新为“已交付” |

HEAD、OPTIONS、网页 `prepare` 选源预检、测速和 `/hls/` 子清单、分片请求不单独生成播放记录。影片重新打开、新建会话或换源会产生新记录，不按影片 / IP / 时间猜测合并，避免把不同客户端的播放混在一起。没有经过本服务的 CDN 直链访问无法记录。

“已交付”表示播放地址、清单或媒体响应开始交付，不能证明客户端完整观看。302 后的视频数据直接走 CDN，本服务无法确认起播、观看时长或结束；网关直连记录也只证明地址已经返回。因此这里展示交付记录，不计算完整观看次数或观看时长。

选择源前失败显示“未确定 / 尚未选源”；不会把失败的候选站点当作最终播放站点。交付前 HTTP 错误显示失败；本服务直接传文件时响应开始后的服务端异常显示传输中断。分片异常仍在原有播放日志中，普通停止播放不标为交付失败。

## 网关关联

已经选择源的中转地址复用现有 `s` 会话。强制中转及回退路径尚未选择源时，在返回的 `/play/...` 地址增加 `ph` 关联参数；真正播放后补齐实际站点与源，并更新原记录。调用方需原样保留 URL 查询参数。现有 embyGateway 转发代码保留查询串，无需为此修改网关。

`ph` 用于关联记录，不承担播放鉴权，原来的 `t` / resolve Bearer 令牌要求继续适用。列表接口不公开会话键、播放令牌或 CDN 签名地址。请求来源地址取本服务实际连接的客户端；经网关时可能是网关地址，不据此推断 Emby 用户身份。

网关或播放器缓存重用同一会话时合并为一条交付记录。网关重新请求解析并建立新会话时产生新记录；本服务没有网关用户 / 播放活动回报，无法把所有外部请求识别成个人观看历史。

## 存储与保留

启动执行 SQLite v20 迁移，新增独立记录表及时间、方式、站点索引。记录不关联全影片库统计，不逐片扫描、不探测源站。已有播放日志不自动回填，记录从升级后开始。

播放路径只提交到有界队列，后台串行写入；同会话的重复请求在内存合并，分片不触发记录写入。记录写入不清除影片查询缓存。正常退出时排空待写入队列；进程被强制终止时，尚未落盘的少量记录可能丢失。队列满或数据库写入出错时保留播放交付，写日志；页面显示本次运行因队列满跳过的次数。

设置页“播放记录”分组提供：

- 是否记录新播放，默认开启；关闭后已有记录仍可查询。
- 保留天数，默认 90 天；0 关闭按时间清理。
- 最大条数，默认 100,000 条；0 关闭按条数清理。
- 待写入容量，默认 2,048 条；修改后重启生效。

保留策略由现有后台维护周期执行，按时间和最大条数清理最早记录；两个限制都为 0 时不自动清理。播放记录与 40 万部影片的存量分开增长，没有访问过的影片不会生成记录。

## 查询 API

`GET /api/play-history` 使用控制台既有登录保护，支持：

- `mode=proxy|redirect`、`site=jable|missav|...`、`state=issued|delivered|failed|interrupted`。
- `q` 搜索影片 slug、番号或标题。
- `since`、`until` 是 Unix 秒，范围为 `[since,until)`；页面日期按浏览器本地时区计算，结束日期包含当天。
- `limit`（默认 50，最多 200）、`offset`。

返回 `{items,total,counts,enabled,dropped,retention_days,max_entries}`。`counts` 针对当前筛选范围，不是仅当前页；方式数包括地址已返回的网关记录，结合状态判断实际交付阶段。队列异步落盘，页面每 10 秒刷新，也可手动刷新。

## 本地验证

新增 5 个测试覆盖真实播放响应的方式与站点、预检/分片排除、网关记录关联、Range 合并与进程重启恢复、登录与停用、队列满不阻塞、保留策略。

Edge 无头浏览器使用独立临时库和模拟上游完成 7 项流程：播放入口、75 条记录分页、方式/站点/影片组合筛选及刷新保留、网关地址状态区分、本地日期筛选、读取失败重试、390px 深色布局。没有页面脚本错误，已目视检查截图。

以上不代表真实源站、生产迁移或 Emby 网关实机播放验收。
