# 媒体库管理：操作与文件影响指南

统一入口：侧栏 **媒体库管理**，或 **输出库与订阅 → 管理文件与记录**。输出库页保留配置和订阅，不再摆放一排含义相近的文件操作。

管理首页先选库，再按“我移动了文件”“我手动删了”“我误删了”“我改了地址”“磁盘有文件没纳管”选择处理方式；下方速查表可按旧名字搜索并展开文件影响。盘点、清理、资料补全、STRM 导入和恢复都在同一管理导航中。旧 `#/strm` 链接仍能打开对应工具，旧维护任务链接仍可继续查看。

## 先分清四件事

1. **影片资料**：数据库里的影片身份、源站、标题等；不等于磁盘文件。
2. **输出关联**：一部影片属于哪个库、主 STRM 记在哪；不等于“所有已存在文件都会被自动发现并收录”。
3. **磁盘文件**：STRM、NFO、图片、字幕、预告片等。删掉文件不一定会删除关联，之后也可能被订阅或核对补回。
4. **Emby/Jellyfin 的库**：它有自己的扫描及缓存；本项目改了文件和记录，不等于媒体服务器立即同步，也不会调用其刷新 API。

### 自管库与外部整理库

- 自管库没有 `external_dir`：本项目按模板写 STRM，并按设置写 NFO、封面。模板变化可能迁移文件。
- 外部库有收件目录和外部整理目录：本项目主要送 STRM，由外部工具移动、改名和刮削。按 STRM 内容识别影片，不仅看文件名。
- **一个库的目录范围不包括其他库或任意库外目录**。跨库移动、移动到未配置目录不能指望“同步位置”自动转移归属。

## 操作速查

| 操作 | 记录影响 | 文件影响及边界 |
| --- | --- | --- |
| 盘点磁盘与 NFO | 更新维护索引、可识别的已有输出路径 | 不改媒体文件。外部库仅盘点外部整理目录；不是收件目录扫描，不自动纳管未知影片。 |
| 强制重读 NFO | 重新解析并更新索引 | 不改 NFO；“强制”是指不复用缓存，不是覆盖文件。 |
| 同步位置 | 更新已有输出关联的路径 | 查本库收件和外部目录，不移动主文件、不补主 STRM、不改 NFO/图片。**多画质开启时，可能新增、改写、删除本服务的版本 STRM**。 |
| 核对输出 | 记录检查结果，也会同步外部库位置 | 本轮界面默认不补回，但外部位置同步仍可能对齐多画质 STRM，不能称完全只读。显式勾选补回后可重新生成缺失输出，见后文。 |
| 重写输出 | 保持/更新输出路径 | 普通库重写 STRM，按设置重写 NFO；模板变化搬匹配资源、删除旧 STRM，目标同名资源已存在时旧侧文件可能删除。外部库已定位输出通常只原地改 STRM，待输出/换库可触发已有迁移逻辑。会对齐版本 STRM。 |
| 重新归库 | 重算规则归属，再做全局来源/排除归并 | 可能新增输出、移库、删旧输出或回收资源，不只是改标签；当前库按钮也可能影响关联库。**没有逐文件预览**，现在先显示影响确认。 |
| STRM 扫描 | 更新 STRM 文件索引 | 不改文件；扫描范围由输入目录决定。留空为输出根，不代表覆盖所有外部目录。 |
| 纳管 | 为识别出的影片建立输出关联 | **不是仅登记路径**：改写 STRM 地址；普通库可按模板搬 NFO/主图、删除旧 STRM，外部库通常原地更新。缺影片时目前只尝试 Jable 详情。 |
| 批量改前缀 / 回滚 | 保存变更记录 | 原路径改 STRM 内容，不搬目录、不改 NFO。先预览；回滚时变化文件会跳过。 |
| 资料兜底补全 | 更新任务、必要时更新接管路径 | 缺文件、补空字段、未整理接管三个模式独立。前两者不搬影片；接管搬到外部库 `_hls补全/{slug}/`，核验后移除源文件。 |
| 只清理资源文件 | 保留影片关联，记住主动清理的资源禁补 | 只处理选定类型如 NFO/主图/剧照/字幕，不删主 STRM。可回收或永久删除；**默认额外图片为永久删除**。 |
| 删除影片副本 | 移除选定范围输出，可禁止再次收录 | 按预览处理 STRM、NFO、图片等整组已识别文件；可选当前库或全局。默认回收，选择永久删除或回收 0 天则无法恢复。 |
| 磁盘已删，同步记录 | 清理经复核缺失的关联，可禁止再次收录 | 不再次删除残留 NFO/图片。用于文件已被手动删除，不用于文件还在的整片清理。 |
| 清理残留目录 | 保存独立检查和执行记录 | 找外部库没有主影片、只剩资源的安全残留目录；确认后整目录回收，保留 0 天可能永久删除。不是清理仍有 STRM 的影片。 |
| 无可用源归档 | 移出选定库并停止收录，保留恢复凭据 | 移到库外归档，不自动过期，也不保证释放空间。仅依据本地源/站点/线路策略，不联网探测播放是否真的失败。 |
| 恢复回收/归档 | 恢复相应关联、解除本次操作产生的规则 | 按原任务预览把文件搬回，有冲突不覆盖；过期或永久删除不能恢复。 |
| 解除禁收/禁补 | 只解除规则 | 不恢复已经删除的文件，只允许以后再收录/补写。 |
| 删除输出库 | 删除库记录及关联；被引用时阻止 | 可只删记录保留文件。若连文件一起删，普通库删除匹配 STRM/NFO/主图；外部库删除主/版本 STRM，外部 NFO/图片保留。不是整片回收。 |

### 重新归库与移出影片为什么危险

普通库移出会调用既有输出删除逻辑，删除主 STRM、对应 NFO/主图和本服务版本 STRM，不是统一送入维护回收区。

外部库移出通常先删除 STRM，再将符合独占条件的资源目录放进库内 `.hls2strm-trash`；全局回收天数为 0 时可直接删除。开启“换库时搬运已整理的目录”且满足条件时，会搬整个整理成果到目标库，而不是重新刮削。共享或不安全目录不强制搬空。

因此，如果你的目的只是“这部片不要了，并且要可恢复”，优先用 **清理文件 → 删除影片副本 → 回收 → 固定文件预览**，而不是用重新归库代替删除。

## 手动动过文件之后

### A. 同一库内改名、移动

1. 确认 STRM 内容没有改成别的影片地址，挂载正常，新位置还在本库的配置目录范围内。
2. 外部库使用 **同步位置**。它同时查收件区和外部区；多画质开启时注意版本文件副作用。
3. 如果先要求完全不改媒体文件，用 **盘点与资料 → 扫描磁盘与 NFO**，但外部库只盘点外部区。
4. 自管库可先盘点找回记录；**重写输出会按模板归位**，不能用它保证手动命名永久保留。

### B. 移到其他库或库外

1. 不要先补回旧路径，否则可能重复生成并再次送刮。
2. 先明确新位置应该属于哪个库、是否调整配置目录，或把文件移回原库范围。
3. 需要接管已有 STRM 时，扫描新目录、确认识别结果及目标库后纳管；它会改地址且可能移动文件，不是只登记。
4. 跨库移动后旧关联不会自动消失，确认目标已正确纳管、没有规则冲突后，再在原库盘点并处理失效关联。库级停止收录会阻止它再次回到原库，不代表所有库禁收。
5. 对复杂跨库整理优先使用影片列表的应用内操作及预览，不手工先挪一半再运行归并。

### C. 主动删除，不想补回来

1. 先确认不是磁盘掉线或挂载变了。必要时暂停本服务调度、对应定时清理和外部刮削。
2. 经常手动删除的库，建议在删除前成功盘点建立基线，在 **手动删除后 → 缺失处理策略** 设置“缺失先等待确认”。这样后续遇到缺失不会直接补回。
3. 删除后再盘点，选择缺失条目，使用 **磁盘已删，同步记录**，保留“完成后停止收录”，检查范围后执行。
4. 只删除 NFO/图片不算整部影片删除；如果不希望资源被本服务补回，优先使用带资源禁补记录的应用内清理。MDCNG 不遵守本服务的禁补规则，需要单独配置。
5. 遗留 NFO/图片不会被记录同步顺便删除；需要时另外检查残留目录。整库清空需已有成功基线、相同根目录身份及明确确认。

### D. 误删，想恢复

- 本服务回收/归档过：去 **记录与恢复** 找原任务，先预览恢复。
- 手动删除的主 STRM：可用 **检查输出 / 补回误删文件**，显式打开补回。普通库按设置生成；外部库找不到时按策略补到收件区。缺失等待确认策略可能阻止自动补回，需要先核对该策略。
- 外部 NFO/图片：核对功能不会恢复它们。优先用备份；没有备份时尝试资料补全，但不能保证还原原图、剧情、评分和人工修订。
- 永久删除的文件：解除禁收不等于恢复。原始刮削成果不能凭数据库完整重建。

## 回收、归档和旧任务

- 回收：文件移入库内回收区，按期限清理；同盘回收一般不立即释放空间。
- 归档：文件移到配置的库外归档目录，不自动过期，确保媒体服务器不扫描该目录。
- 永久删除：不能从本服务恢复；回收保留 0 天也可能走此路径。
- 旧版“目录占用与图片清理”任务仍可从 **全部任务** 查看原清单、继续处理；它只永久清 extrafanart 图片，并非新维护功能的所有资源禁补流程。新操作统一推荐使用“清理文件”。
- 前缀回滚在 STRM 子工具中；已完成的旧残留检查在对应任务详情中确认；资料补全有自己的历史。不要把所有“恢复”当成同一种回滚。

## 后台与范围边界

订阅、归并、同步多版本、核对补回、回收区到期清理，都可能在你手动操作时修改文件。全局暂停主要停止领取业务任务，**不等于关闭所有定时清理**；应同时检查定时任务，外部刮削器也要单独暂停。

本管理首页展示的是库级范围，不把从影片列表带入的筛选悄悄扩大成全库操作。带影片筛选或多库选择进入仅支持单库/目录的工具时，会先阻止并要求明确范围。站点清退属于另一个全局工具，不受首页单库选择限制。

本轮仅调整前端组织、提示及确认默认值；不改变后端纳管、归库、清理或订阅算法，不修改现有定时计划，不执行真实媒体文件操作。
