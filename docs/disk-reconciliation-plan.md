# 按磁盘核对并停止收录：待审核方案

后续需求已统一纳入 [媒体库维护统一规划](library-maintenance-plan.md)。本文保留为早期范围记录；实施以统一规划为准。

## 目标和现状

用户主动删除有问题的影片后，同步清除失效的输出库关联，并阻止以后自动重新收录。

当前 `strm_manage.py` 的位置同步保留缺失记录；`engine.py` 的 `restore_lost()` 在配置允许时补回 STRM。单独删除 `outputs` 记录不能阻止订阅和规则再次加入。

现有 `sources.status = removed` 只屏蔽指定来源。`db.py` 的 `_attach()` 可以给旧作品添加其他站点的新源，`_update_work()` 会将其重新标记为 active；`tests/test_remove_source.py` 明确测试了这一行为。因此不能把“删除已有源”当作“永久停止收录作品”。

## 建议的第一期行为

1. 输出库菜单新增「按磁盘核对并停止收录」，手动启动后台只读预览。
2. 只检查曾经成功输出、数据库保存了 STRM 路径的影片；不处理尚未写出的待归库记录。
3. 按 STRM 内容同时查收件目录和外部整理目录。被改名、移动的文件更新位置，不视为删除。预览还需检查其他已配置输出库：其他位置仍有副本时列为“仍有文件”，默认排除，避免因一个库缺失而全局屏蔽影片。
4. 预览列出影片、版本、库、原路径和缺失原因，允许选择确认的影片。冻结选择范围，执行前重新检查，已恢复或发生变化的条目跳过。
5. 对确认缺失的影片，删除失效的输出库关联，设置独立的“主动删除／停止收录”标记。保留作品身份、来源和操作原因，用于防止重新导入和手动解除，不对其他现存文件执行删除、搬运或归档。
6. 正常影片列表不再把它们当作在库影片，增加「已停止收录」筛选及「允许重新收录」操作。解除后恢复正常收录资格，不承诺立即重建已经删除的刮削文件。

只删除额外剧照、封面或 NFO，不会触发停止收录；确认依据是管理的 STRM 在可用目录中真正不存在。

## 屏蔽范围

建议按当前数据库的影片身份全局停止收录，覆盖所有站点的新旧来源和输出库；普通版和 `-U` 版沿用已有的独立身份，不合并屏蔽。

需要覆盖列表抓取、详情回填、自动/手动补源、前缀补源、规则/来源库归并、手动加入、核对补回、重写输出，以及已排队任务的执行前检查。停止收录独立于 active/gone/removed 源状态，发现新源不能清除此标记。手动加入也需先明确解除。

若实际需求只是“以后不要放回某一个输出库”，应改为库级排除记录；这与全局停止收录的作用范围不同，实施前需要确认。

## 数据及执行约束

- 增加独立、持久化的停止收录字段/记录，记录时间、原因及来源任务，不物理删除作品身份。现有迁移升级，默认全部未屏蔽，不改变已有收录行为。
- 根目录不可访问、读目录失败或挂载异常时不生成可执行的删除结论。整库突然为空不能直接批量屏蔽，必须单独处理“确认主动清空”的情形。
- 复用现有后台任务、固定范围预览与确认机制；执行期间与应用内文件变更互斥，并核对状态。
- 第一阶段采用手动预览确认，不把周期性位置同步直接改成自动退库。为避免旧补回逻辑先行恢复文件，操作期间需暂停相关抓取/补回任务；确认后的影片由独立标记持续保护。
- 不修改 MDCNG、Emby 或 Jellyfin 的数据库，它们的磁盘扫描由各自负责。

## 验收

- 删除一部影片全部文件后，被正确识别并在确认后移除失效关联；重新抓到同站或其他站源均不再输出。
- 改名、跨目录移动、只删图片、待归库影片、其他库仍有文件都不会被误屏蔽。
- 目录离线、权限错误、预览后文件恢复都不会造成错误退库。
- 重启、任务重试、并发抓取不能解除屏蔽；手动解除后可以再次收录。
- 普通版和 `-U` 版保持独立，未选择的影片和现存磁盘文件保持原样。
