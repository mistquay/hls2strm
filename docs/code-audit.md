# 升级前番号审计（P0）

```sh
python -m hls2strm.code_audit --db /path/to/hls2strm.db --out groups.csv
docker run --rm -v ./data:/data:ro <新镜像> python -m hls2strm.code_audit --db /data/hls2strm.db
```

建议使用数据库副本。SQLite 使用 WAL 时应先取得一致的备份；不要只复制主库而遗漏尚未合入的 WAL 数据。
工具使用 `mode=ro` 连接，在一个只读事务内读取，不运行迁移、不导入业务数据库模块，也不扫描媒体文件。
支持升级前的 v21 表结构；模块随 Python 包进入镜像，无需额外安装依赖。

终端列出键变化数、全部同版重复组及输出记录、疑似冲突组、有兄弟版本的作品数。
重复组按非空 v2 键与 `edition()` 规整后的版本分组；兄弟版本数按影片行计数，包含所有状态，
不是可播放备用数量。原生无码的旧 `uncensored=1` 会按普通版参与预测，但不修改原记录。

两部都有详情且已知的发行日期不同，或已知时长差超过 `max(120 秒, 较长时长的 10%)` 时，
列出冲突的影片 ID 和原因。缺详情、缺日期或时长不是冲突证据，也不代表已确认同片。

路径归属仅比较 `outputs.strm_path`、`libraries.external_dir` 和数据库设置里的 `output_dir`，
支持 Windows 和 Linux 路径。相对整理目录缺少可确定的输出根目录时标记“无法判断”，
不猜服务器环境变量或用本地副本位置代替服务器路径。文件是否存在、是否已被移动、是否被 Emby 收录，
不在本阶段的审计范围内。

CSV 使用 UTF-8 无 BOM，每部重复影片的每条输出一行；没有输出的影片也保留一行。
包含新旧键、原版本、slug、状态、详情证据、库、路径和冲突原因；不覆盖已有文件。
审计与业务共用 v2 算法；审计命令本身不启动业务、不执行 P1 迁移或 P2 整理。
