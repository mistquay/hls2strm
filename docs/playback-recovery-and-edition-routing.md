## 边界

普通版和 -U 版仍独立，起播备用由既有配置控制；`@720p` 等只表示画质。
已开始传输的媒体不跨源续传。用户移除的源不自动恢复。
搬运失败不得继续删除已刮削目录，目标已有文件不得覆盖。
MDCNG 和 Emby 的历史数据库不直接改写。部署前不启用旧服务不认识的版本规则。
工作区原有抓取器、站点信号、部署文件等改动保留；按用户后续要求仅提交本任务，不推送。

## 实现

- `play.py`、`playback_selection.py`：失败排除不再阻止发现新源；用请求上下文限制一次发现。多线路源的解析和 CDN 预检各受单次预算约束，避免一个源耗尽总预算。起播失败按小时去重排后台补源，尊重负缓存和已移除的源。
- 文件中转先读第一块，再返回响应头。连接、HTTP 状态、错误页面、空内容和首包失败可以换源；本地连接池拥塞不惩罚源。非零 Range 和显式选源不自动换源。
- `/media` 首次失败返回 307 到新的绑定会话，保留令牌、档位、字幕/直连/版本限制和已失败候选。原会话固定记录替代地址，重复请求不会反复挑源。交付标记落库，重启后仍禁止跨源续播。HLS 已发出清单后不跨源替换分片。
- `rules.py`：版本作为一组条件参与既有 any/all 组合；原生无码番号按普通版处理，不等同于“有码”。
- `relocate.py`：整目录搬运保留 STRM、NFO、图片和画质附件，先写恢复凭据再搬文件；移完未写库可恢复，跨盘复制中断则保留两端等待核对。目标冲突、不可访问或软链接路径不退回删旧写新。共享目录仍按原流程只移出本片文件。
- 搬运功能默认关闭，迁移脚本执行时显式开启。预览的“候选搬运”是数据库归属推算，实际目录独占性、位置和挂载在执行时核对。

## 部署后执行

脚本在工作站运行，通过 hls2strm 管理接口调用已有预览/确认/后台任务机制。
默认目标库 7、原生库 4；可用 `--target-library`、`--native-library` 覆盖。
密码交互输入，或使用 `HLS2STRM_ADMIN_PASSWORD` 环境变量。

先暂停 MDCNG 对相关目录的监控和整理，并备份 hls2strm 数据库及整理目录。
确认容器可访问目标整理目录 `/mnt/hls2strm_matched/decensored`，各库采用相容的目录模板。

```powershell
# 只生成预览；旧镜像会被版本能力检查拒绝，不修改配置。
python scripts/route_editions.py --url http://38.46.221.197:18090 --user admin

# 只执行版本归库、更新流出订阅和库名，不创建存量补源任务。
python scripts/route_editions.py --url http://38.46.221.197:18090 --user admin --apply
```

执行顺序：开启搬运 → 同步位置 → 预览并应用库 7 的 `edition=u` 规则（保留中文字幕/FC2 等排除关系）
→ MissAV/123AV 的 `uncensored-leak` 订阅改到库 7 → 库 4 改名“原生无码”。
每步保留报告，任务部分失败就停止；恢复时先在任务页处理未完成的库变更，再重跑。
文件移动后不要只还原数据库：恢复凭据在服务数据目录 `relocations/`，两端文件需要一起核对。

已有 NFO 和图片被保留，但脚本不更新 MDCNG 历史记录中的 `target_path`，也不能保证 Emby 换库后的条目 ID 和观看记录不变。
完成后恢复 MDCNG 监控并让 Emby/FYMS 扫库，避免让 MDCNG 按旧历史路径直接重新整理。

## 存量补源与播放影响

迁移脚本不再提供 `--probe`，避免在归库完成后继续等待数万部补源。
页面“查找其他源”生成的 probe 子任务使用普通后台优先级 0，订阅列表任务优先级 10、普通用户任务 20；其他批量操作的优先级保持原状。
播放不经过任务队列：抓取连接池和播放连接池、站点播放并发独立，播放解析跳过后台站点限速。
但出口 IP、CPU、SQLite 写入和磁盘仍共享，源站限流/封禁也会影响播放解析，因此不承诺零影响。

部署后先只归库。需要补存量时，建议在影片库筛选目标库、单源片和缺少 MissAV，选中一页（默认 50 部），在“查找其他源”中选 MissAV。
先观察实际播放与任务错误情况，再决定后续批次；123AV 单独处理，不同时开两个站的大批任务。
如有影响，在任务页暂停该补源任务，不用关闭站点或暂停整个调度。已在执行的请求可能继续到完成或超时。
新片自动补源和播放失败补源保留，避免必须先补完整个库存才能使用。
单站后台并发可调为 1；不要同时降低播放并发，也不要误把后台任务优先级当成 CPU/磁盘隔离。
归库阶段也会扫描目录、更新大量归属；跨盘移动会复制文件，应安排在播放低峰。
