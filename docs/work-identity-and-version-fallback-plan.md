# 通用番号别名、独立内容版本与可选起播备用

状态：修订设计稿，尚未实现或迁移。2026-10-13。

## 设计结论

普通版与 -U 版继续保持独立影片、独立元数据、独立归库和独立 STRM。
只在同一内容版本内归并番号别名；不同内容版本通过作品键关联，可配置互为起播备用。
本稿替代上一版“一作品一主 STRM、默认跨版本备用”的建议。

```text
作品关联 LUXU-1850（仅用于查找，不是新的输出条目）
├─ 普通版影片 luxu-1850
│  ├─ 普通版的源
│  └─ 主 STRM、本版 @720p / @1080p 等画质文件
└─ -U 版影片 luxu-1850-u
   ├─ 源 luxu-1850-u 对应页面
   ├─ 源 259luxu-1850-u 对应页面
   └─ 主 STRM、本版 @720p / @1080p 等画质文件
```

截图三条逻辑影片归成两条；已有物理文件的数量可以暂时不变。

## 一、核对到的现有行为

| 功能 | 代码证据 | 本次边界 |
| --- | --- | --- |
| 同版影片归并 | `db.py:_attach` 按 `code_key + uncensored` 匹配；已有源沿用旧归属 | 扩展通用番号别名，保留内容版本边界 |
| 多画质输出 | `engine.py:version_labels`、`writer.py:sync_versions`；库 `versions` 为关闭/emby/suffix | 按独立影片汇总本版画质，不混入另一内容版本 |
| 画质播放入口 | `play.py:_parse_name` 解析 `{slug}@720p` | `@` 继续专用于画质，不改为内容版本编码 |
| 外部整理库 | `writer.py:write` 原地更新已有 STRM；缺失时等定位；不写 NFO、不搬目录 | 别名识别不触发改名、重刮或整体重写 |
| 整理后画质文件 | `engine.py:sync_versions` 在收件目录不写，整理后在主文件旁补 | 保留当前时机和布局 |
| 画质文件所有权 | `writer.py:own_versions` 按路径模式和精确 slug 识别 | 不按整个作品分组扩大删除范围 |
| 同步位置 | `strm_manage.py:find_by_video` 忽略画质文件；`locate` 每影片/库选一个主路径 | 接入旧别名、保存多个历史入口；不能只留一条 `strm_path` |
| CDN 直链输出 | `play_mode=direct` 可把 CDN URL 写入 STRM | 直链文件不经过本服务，开启备用配置本身不能使其获得备用能力 |

当前 `tests/test_versions.py`、`tests/test_strm.py`、`tests/test_multisite.py` 共 12 项通过。
这验证现有行为，不代表新功能或真实 MDCNG/Emby 迁移已经验收。

## 二、作品身份、内容版本、画质三个维度

- 作品键判断是否同一作品，供关联查找，不决定输出去重。
- 内容版本决定独立影片归属、元数据、分类、主 STRM；普通/-U 不合并。
- 画质继续使用已有版本文件和 `@画质` 机制，不与普通/-U 混用。
- 字幕继续使用现有源级策略，不借本次改造扩大字幕输出模型。
- 保留原生无码、破解、流出、未知的区别；不能把所有无码都视为某普通版的 -U。
- 未知版本不默认普通，不自动并入 -U；详情补全或人工确认后再确定关联。
- 分段或明显不同剪辑不因基础番号相同自动互备。

### 通用身份解析

站点适配器提供原始番号、标题、厂牌、key 和版本证据，公共解析器统一处理：

1. 大小写、全角、适用系列内的分隔符和补零。
2. FC2 等已验证写法、数字厂牌前缀的集中别名规则。
3. 站点已确认的 -U、uncensored-leak/leaked、REDUCING-MOSAIC 等版本写法。
4. 日期型番号的厂牌命名空间；厂牌未知时不凭日期数字跨站自动归并。
5. 正式编号中的厂牌数字、系列数字和分段后缀。

`259LUXU ↔ LUXU` 是通用规则表的一条，不是专用功能分支。
不能删除任意数字前缀；已有 `300MIUM`、`T28`、`KIRA-020-2` 和日期分隔符边界保留。
站内兜底 ID 只能作为该站源身份，不能冒充全局作品番号。
标题、封面或演员相似只做辅助提示。已验证规则且证据无冲突才自动关联；不明确的进入待确认。
人工“同版别名/不同版本/保持分开”的决定持续生效，后续抓取不得覆盖。

## 三、在现有模型上演进

继续使用 `videos -> sources -> source_lines`：

- `videos` 仍代表独立输出的内容版本，保留自己的 ID、slug、元数据、分类、状态及输出关联。
- 增加或明确规范作品键与内容版本身份；普通/-U 作品键相同、影片 ID 不同。
- 同版别名归并到一个规范影片，保留旧 ID/slug 映射和原始记录快照。
- `sources` 保留原始 key/番号、必要的识别证据与时长，以及原有字幕、直链、健康和线路。
- `outputs` 仍按内容版本影片 ID/库记录主输出，不改成作品分组级输出。
- 增加受保护的历史输出关联，保存每个旧主 STRM、原入口 slug、库、文件身份及其画质附件。
  此记录必须持久，不能依赖下一轮扫描就替换的缓存，也不能只保留一个路径。
- 原有 `source_checks(video_id, site)` 已由影片 ID 区分内容版本，可以保留；补源要记录候选覆盖范围。
  别名规则更新后重查相关负结果，不能因已有该站一个源就永远不查同站其他别名页面。

人工删除的源不因归并复活；普通/-U 的分类、归库、下架和删除状态独立。
备用成功不把本版标成源已恢复，不把备用源永久挂到被请求版本。
主元数据采用稳定优先级和人工覆盖，规范展示番号不自动改变路径或播放 slug。

## 四、配置化起播备用

建议设置：“允许同作品其他版本起播备用”，默认关闭。
全局设置提供默认值，单影片支持“继承/关闭/开启”。
只有身份确认且内容关系适合备用的版本参与；未知、冲突、分段不同的记录不参与。
普通入口先尝试普通版，-U 入口先尝试 -U，不设置默认“-U 抢占普通入口”。

```text
请求普通入口 -> 本版候选和起播预检 -> 失败 -> 配置开启 -> 同作品 -U 候选
请求 -U 入口 -> 本版候选和起播预检 -> 失败 -> 配置开启 -> 同作品普通候选
```

- 本版沿用现有字幕、健康、画质、站点和线路选择；不因另一版更高清就提前换版。
- 起播解析/预检失败后才能备用；手动锁定源/版本、字幕不回退、直连要求和显式排除不能被绕过。
- 优先复用已有关联源；现场补源共享原有总预算，不给每个内容版本重新计时。
- 补源归入实际内容版本，不把两版源永久混在一起；后台任务扩大覆盖，现场查找保持有界。
- 缓存包含请求影片 ID、备用开关及原选源条件；会话记录请求版本与实际源版本，固定源/线路/直链。
- 页面和日志注明“请求普通版，使用 -U 起播备用”，不改本版 NFO、归库或质量清单。
- 播放开始后的自动恢复不重新跨内容版本选源；剪辑不同不能直接沿用进度。
- 外部播放器断点续播也可能有时间轴差异；普通 STRM 请求无法可靠判断续播位置。
  要求精确续播/版本的场景保持备用关闭，不承诺跨版本进度等价或交付 302 后动态换源。
- 备用必须经过本服务解析。已有 CDN 直链 STRM 列为“需转换入口”，审核后可原地改内容，
  不因开启备用设置自动重写旧文件。

## 五、多画质兼容合同

保留 `libraries.versions`、`version_min_height`、`variant_mode`、`quality_first`、画质上限和原选档规则的含义。

1. 普通版画质清单仅来自普通版源，-U 画质清单仅来自 -U 源。备用开关不触发版本文件增删。
2. 不把普通版独有的 4K 生成到 -U 版旁；同版别名新增源时可按现有机制增加本版画质。
3. `@720p` 请求跨版备用时必须透传 `want=720`，沿用原选档规则，不能清空要求改成最高档。
   本次不把现有画质偏好改为精确画质保证，也不另改画质降档行为。
4. 保留 Emby/suffix 命名；外部库继续整理前不写附加画质文件，整理后在原主文件旁补。
5. 旧 `259luxu-1850-u@720p` 映射到规范 -U 影片并保留 720p，不落到普通版或丢掉画质信息。
6. 附件归属按原入口、父主 STRM、路径和程序生成记录确定，不能把整个作品组的附件当作自己的。
7. 同目录多个主入口可能争用同一 Emby 风格画质文件名；发现冲突报告并跳过，不覆盖已有文件。
8. 别名迁移不能直接调用普通“重写所有输出”或“关闭版本后清理”；迁移预览必须列出附件影响。

## 六、历史 STRM、刮削器与 Emby

### 默认：逻辑归并，物理保留

同版别名在 hls2strm 中显示为一个影片、共享源池；已输出的多个入口文件和旧 URL 继续有效。
保留所有主入口与画质附件关联；主输出优先已确认的外部整理成品，多个成品主次不明时报告。
未来发现同版别名不再生成额外主 STRM。历史副本不由普通归库、缺失补回或自动去重删除/重建。
历史入口保留原内容版本身份，显式画质设置变更按各入口附件归属执行，不扩大到另一版。

| 历史情况 | 默认处理 |
| --- | --- |
| 普通/-U 都已输出或收录 | 都保留，仅增加可配置备用关系 |
| 同版一份已整理、一份仍在收件目录 | 已整理目标优先作为主输出；收件副本列入可选归档预览 |
| 同版两份均已被 Emby 收录 | 文件和旧链接都先保留；共享源池，Emby 仍可能显示两项 |
| 外部工具改目录、改文件名 | 按 STRM 内容和旧别名定位，优先有效的已记录路径，不按规范番号重建 |
| 多画质附件 | 作为主入口附件，不当重复影片或主 STRM |
| 挂载、位置或归属不明 | 保留并提示，不当成丢失，不清理 |

NFO 的存在不能证明 Emby 已收录；无 Emby 只读证据时收录状态标未知。
保留路径和元数据能降低条目变化风险，但不能凭本项目数据库保证 Emby ItemId/观看记录不变。

### 可选：减少 Emby 同版重复条目

这是独立维护操作，不是番号识别的默认副作用：

1. 预览真实主 STRM 路径、内容版本、附件、刮削证据，以及可取得的 Emby ItemId/观看状态。
2. 用户选保留项，验证保留入口和旧别名都能起播。
3. 列出精确归档文件；共享 NFO、封面和目录不整目录搬走。
4. 暂停相关外部写入后，用无覆盖、可恢复、有日志的方式归档；离线、文件变化或冲突时停止该组。
5. 再扫描对应 Emby 库，验证剩余条目与用户数据。观看状态迁移/条目合并属于 Emby 侧能力，单独确认验证。

旧 URL 兼容不能让 Emby 忽略仍存在的第二个文件。
若要求每个旧条目和观看记录完全不动，采用物理保留模式，接受同版重复项暂时存在。
不直接修改刮削器或 Emby 内部数据库。

## 七、实施阶段和验收

1. 通用身份解析与只读预览：区分同版别名、不同版关联、冲突、未知及全部旧入口附件。
2. 同版源池归并与别名兼容：保留普通/-U 独立 ID，保存旧 ID/slug、源/线路、历史输出、删除状态和既有会话。
   持久任务记录前后关联及规则版本，支持中断续做和回滚；协调暂停相关写入。
3. 默认关闭的起播备用设置：只影响后续解析，不触发改名、重刮、重新归库或画质文件更新。
4. 独立的历史重复文件预览/归档/恢复操作；选择物理保留时不执行文件变更。

兼容记录先准备，再切换匹配规则，避免旧链接变陌生文件、旧任务又建重复影片。
数据库升级不自动移动/删除文件；同版新源更新仍按已有正常输出流程执行，并保护人工数据和历史路径。

验收至少覆盖：

- 示例三条归两条；普通/-U 元数据、归库、源删除和输出独立；多系列别名无误合并。
- 备用关闭不跨版，开启仅本版起播失败后使用；锁定、字幕、直连、时间预算仍有效。
- 备用不改变源归属、NFO、分类和版本画质清单。
- 两种画质命名、至少两档、最低档、最多七个附加档、更新、关闭版本、移出库的现有测试保留。
- 全部旧 slug 与 @画质链接有效；定位不选画质文件作主入口，附件清理不跨内容版本。
- 外部整理前后写入时机保持，旧别名定位与多个历史入口可追溯。
- 归库/重写/补回不移动成品、不复活删源、不清理受保护副本；直链能力限制明确。
- Emby 历史保留与可选归档分别验证；离线、共享附件、冲突、中断、重复执行及回滚有覆盖。

当前只修订设计文档，没有读取生产数据库、归并影片、变更 STRM 或操作外部刮削器/Emby。
